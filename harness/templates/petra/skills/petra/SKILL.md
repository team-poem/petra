# PETRA 협업

규칙은 `.petra/AGENTS.md`, 실행은 `sh .petra/bin/petra`다. 앱의 테스트·구현 방식을 바꾸지 않는다.

## 처음 합류

`onboard`로 상태를 읽는다. 준비 전이면 "안녕하세요. PETRA는 동료 에이전트에게 지금 하는 작업과 바뀐 계약을 알려줍니다. 사용할 핸들과 먼저 설명이 필요한지 알려주세요"라고 묻는다.
실제 핸들로 `join <핸들>`을 실행하고 `digest --fetch`를 읽는다. 준비된 사용자에게 온보딩을 반복하지 않는다. 원격 조회 실패를 '동료 없음'으로 설명하지 않는다.

## 작업 시작

동료 goal·next·편집 파일을 먼저 읽는다. 새 작업은 main을 기준으로 별도 브랜치/워크트리에서 한다.
`.petra/templates/claim.md`를 `.petra/collab/active/<branch-slug>/claim.md`에 작성한다. slug는 `/`를 `--`로 바꾼다. 실제 owner·branch·goal을 채워 claim만 커밋하고 `git push -u origin HEAD`한다.
같은 부분을 고쳐야 하면 사용자와 순서를 맞춘다. 허브 변경이 크면 작은 선행 PR로 분리한다.

## 작업 중

몇 파일을 수정한 뒤와 동료에게 영향을 줄 결정을 하기 전에 `pulse`를 실행한다. Claude는 편집 훅도 있지만 Codex는 명시적으로 호출한다.
독립된 기능/수정이 검증을 통과했을 때 에이전트가 `checkpoint --message "변경 요지" -- <이번 파일들>`을 호출한다. 기존 staged 파일을 임의로 포함하지 않는다. 이 명령은 테스트를 대신하지 않는다.
타입/API/스키마 계약 변경, 동료 질문, 기다리던 파일의 완료는 **그 시점에** 새 저널 이벤트로 커밋·push한다. 세션 끝까지 미루지 않는다. 미커밋 스냅샷만으로는 이벤트가 전달되지 않는다.
Sobaya 워커는 `run -- <명령>`으로 감싼다. 실행 중에는 워커가 커밋을 소유하며 별도 checkpoint나 merge를 끼워 넣지 않는다.

## 인수인계와 PR

새 저널에 `## 이벤트`, `## 남은 것`을 쓰고 claim 상태를 갱신한다. 기존 저널을 고치지 않는다. 실제 앱 테스트와 `check` 결과를 확인한다.
`pr-body`로 본문 초안을 만들고 실제 검증 결과·동료에게 필요한 조치·Sobaya review HEAD를 채운다. 승인된 plan 보관은 gate/review 뒤 마지막 커밋이다.
요청받은 범위에서 commit/push/PR을 수행한다. main에 직접 push하거나 팀 승인을 대신하지 않는다. 전송 실패 시 로컬 커밋 보존 여부와 재시도 방법을 알린다.

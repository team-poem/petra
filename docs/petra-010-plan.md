PR #8 이후 범위. 공개 README는 소개로 유지하고 절차와 검증 기록은 별도 문서에 둔다.

- [x] 작업 중 공유: 미커밋 스냅샷, 전송/조회 상태, 오래된 정보와 미확인 상태를 구분한다.
- [x] 체크포인트: 의미 단위 완료와 계약 변경 때 에이전트가 검증 후 선택한 파일만 커밋하고 공유한다. 타이머는 코드를 커밋하지 않는다.
- [x] 긴 워커: 실행 중에도 주기적으로 공유하며 HEAD/인덱스/승인 상태를 변경하지 않는다. 종료 시 보조 프로세스가 남지 않는다.
- [x] 설치 수명주기: dry-run/plan 확인, 기존 협업 기록 이전, 관리 파일 업데이트와 되돌리기, 중단 복구를 검증한다.
- [x] 소비자 연결: 최소 스킬/온보딩, PR 양식, 읽기 전용 협업 CI를 배포한다. 기존 사용자 설정을 보존한다.
- [x] 로컬 검증: 두 clone, 실패/복구, linked worktree, 실제 Sobaya 런타임 회귀 및 도구별 동작을 구분해 기록한다. Claude 응답은 인증 제한으로 미검증이다.
- [ ] 최종 PR의 Linux/macOS CI 확인.
- [ ] 릴리스: 버전/노트/재현 가능한 배포물과 CI를 준비하고, 팀 승인과 main 병합 뒤 v0.1.0을 배포한다.

## 지키는 경계

- 기존 승인된 Sobaya 테스트는 바꾸지 않는다. 새 동작은 별도 테스트로 검증한다.
- 사용자 코드/README/Test 명령, `.petra/config.sh`, 팀 저널, 개인 저장소·승인 상태를 업데이트 소유물로 취급하지 않는다.
- 네트워크 실패는 무충돌의 증거가 아니다. 스냅샷에는 `.gitignore`로 제외되지 않은 파일 **내용**도 전송된다.
- Codex의 명시적 CLI와 Claude의 자동 훅을 동일한 자동화라고 부르지 않는다. 모델 접근 실패는 검증 미완료로 남긴다.
- 업데이트는 임의 최신 코드를 실행하지 않고 검토한 제작 리포/배포물을 명시한다. main 보호와 승인 절차를 우회하지 않는다.

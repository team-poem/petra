# PETRA 설치·이전 수용 테스트 계획

상태: [설계안](petra-installation.md)의 검증 계획. 새 테스트 구현이나 기존 승인된 테스트 변경이 아니다.
갱신일: 2026-10-09. 기준: main `823d823`(PR #5 머지). 아래 PETRA 수용 항목은 모두 **미실행**이며 구현 PR에서 실제 결과와 증거를 채운다. 방향 동의를 아직 작성하지 않은 테스트 입력의 승인으로 대신하지 않는다.

## 공통 준비

- 외부로 push하지 않는 bare 원격과 임시 clone 두 개(solp, amazon), linked worktree를 사용한다.
- macOS의 실제 기본 Bash와 shlock, Linux의 Bash와 flock을 별도로 검증한다. 한 OS의 성공을 다른 OS의 증거로 대체하지 않는다.
- 환경의 `GIT_*`, 에이전트 루트 변수, 사용자 global Git 설정을 격리한다. 네트워크·모델 호출은 기본 차단한다.
- 배포 전 파일, 실행 권한, 심링크 대상, Git HEAD·인덱스, 관련 config의 값·scope, Sobaya pin·메타데이터를 스냅샷으로 비교한다.
- fixture 준비에 필요한 훅 우회와 제품 경로의 실행을 구분한다. 검사할 commit/push/설치 경로에는 우회를 넣지 않는다.
- 기존 승인된 테스트를 편집하거나 약화하지 않는다. 새 회귀 테스트 초안과 배치 변경에 필요한 정확한 수정본은 사람이 검토한 뒤 적용한다.

## 4. 실제 에이전트 검증

이 부분은 셸 fixture로 대체할 수 없다. 모델 실행 비용과 로컬 앱 연결이 필요한 검증은 사용자와 실행 범위를 확인한다.

| ID | 상황 | 합격 기준 |
|---|---|---|
| A01 | 새 Codex 세션, root와 앱 하위 cwd | 프로젝트 AGENTS 및 PETRA 참조를 실제 읽고 작업 전에 digest 수행. 파일이 있다는 검사만으로 통과시키지 않음 |
| A02 | 새 Claude 세션, CLAUDE.md 부재 | PR #3의 심링크 제거 결정을 유지하면서 협업 계약을 실제 소비. 지원 경로가 확인되지 않으면 미지원으로 보고 |
| A03 | 도구별 자동 훅 | 사용 버전·발생 이벤트·입력·응답·차단/문맥 전달 결과 기록. 다른 도구와 JSON 모양이 같다는 검사로 대체하지 않음 |
| A04 | 자동 훅 미지원 환경 | 수동 CLI 시작·동기화·handoff와 실제 Git 커밋 검사가 동작. 자동 편집 차단과 동등하다고 표시하지 않음 |
| A05 | 설치 완료 안내 | 사람이 root README에서 앱 실행 방법을 찾고 PETRA 안내 위치를 알 수 있음. 하네스 사용과 하네스 자체 개발을 혼동시키지 않음 |

## 결과 기록과 출시 조건

각 실행 기록은 `ID / PETRA commit·배포 SHA / Sobaya 버전·commit / OS·도구 버전 / 준비 상태 / 명령 / 종료 상태 / 검증한 스냅샷·로그 / 남은 한계`를 포함한다. PASS, FAIL, BLOCKED, NOT RUN을 구분한다. 모델 대역을 사용한 통과는 실제 모델 성능의 증거가 아니다.

필수 범위는 I01-I11, M01-M10, C01-C16과 지원한다고 표기할 도구의 A01-A05다. 총 42개 수용 시나리오이며 자동 테스트 함수 수와 같은 뜻이 아니다. 기존 hooks 84 + loop 48 + sobaya 32 + installed 9 + legacy-worktree 7 + mixed-mode 11 = **191개**의 회귀 결과도 필요하다. 경로 변경으로 실행 입력을 바꿔야 하면 정확한 변경 초안을 별도로 승인받는다. 테스트 수정 승인은 실제 통과나 제품 출시 승인이 아니다.

### 단계별 사용

- 첫 구현에서는 I01·I10, C05·C06·C11·C13·C15와 A01-A04를 우선 관찰한다. [첫 구현 계획](petra-first-slice.md)의 두 clone 시나리오를 먼저 실행하며 설치기·이전 기능이 없는 항목은 NOT RUN으로 남긴다.
- 설치 구현에서는 I01-I11, C01·C02·C09·C10과 A05를 추가한다. 도구별 자동 연결 검증이 미완료면 해당 지원을 표기하지 않는다.
- 이전·업데이트에서는 M01-M10, C03·C04·C07·C08·C12·C14·C16을 완성하고 전체 회귀를 재실행한다. 단계별 우선순위는 출시 조건을 면제하지 않는다.
- 첫 구현의 임시 배치 성공을 정식 배포물 설치 성공으로 대신하지 않는다. 출시 전에는 실제 배포물로 전체 소비 흐름을 다시 검증한다.

이번 설계 브랜치에서는 Markdown 링크·파일 범위·협업 형식만 검사한다. 이 표의 미실행 항목을 구현 없이 PASS로 바꾸지 않는다.

# PETRA 첫 소비 배치 검증

## 이번에 만든 것

쇼핑몰은 자기 README, AGENTS, 코드와 테스트를 루트에 둔다. 협업 실행 코드는 `.petra/runtime/`,
팀 기록은 `.petra/collab/`, 설정은 `.petra/config.sh`에 둔다. 기존 협업 CLI의 판단을 복제하지 않고
동일한 소스 파일을 명시적인 목록으로 패키징한다. 제작 리포의 실제 저널·claim·테스트는 패키지에서 빠진다.
캐시는 각 worktree의 Git 메타데이터 `petra/`에 두므로 앱 PR에 섞이지 않는다.

`pack`은 새 staging 경로에만 파일을 만든다. 기존 프로젝트를 덮어쓰거나 연결 설정을 이관하는 설치기는 아니다.
manifest는 개발 버전, 소스 커밋, 소스 작업 트리 변경 여부, 관리 파일 SHA-256을 기록한다.
작업 트리가 변경된 패키지를 해당 커밋의 정식 릴리즈라고 주장하지 않는다.
`verify`는 관리 파일과 Git 훅 권한을 읽어 확인하며 앱 코드나 사용자 설정은 수정하지 않는다.

## 두 사람 없이 먼저 하는 테스트

```sh
sh tests/petra.sh
```

테스트가 임시 bare Git 원격, 쇼핑몰, solp와 amazon의 두 clone을 만든다.
실제 Git 훅으로 커밋과 push를 검사하고 다음 흐름을 확인한다.

1. 앱 문서와 Test 계약을 유지한 채 각 clone에서 개인 핸들과 훅을 준비한다.
2. solp는 상품 표시, amazon은 장바구니를 선언해 push한다. 원격에서 서로의 목표를 읽는다.
3. solp가 가격 함수에 currency 인자를 추가하고 저널로 알린다. amazon의 새 장바구니 파일이 가격 함수를 import하므로 변경을 받는다.
4. amazon이 package.json을 편집하는 동안 solp의 같은 파일 수정은 막힌다. 상품 화면의 다른 파일은 통과한다. amazon이 커밋하면 편집 잠금이 풀린다.
5. 저널 질문에 답하면 상대에게 답이 도착하고 원래 질문은 더 이상 반복되지 않는다.
6. 새 기록 경로로 check와 PR 본문을 만들고, worktree별 캐시와 명시적인 대상 경로를 확인한다.
7. manifest가 없는 옛 원격 브랜치도 그 브랜치의 collab/에서 읽는다. main 직접 push와 실행 코드 변조를 검출한다.

26개의 검사다. 패키지 파일 존재만 보는 검사가 아니라 실제 원격과 서로 다른 작업 트리를 사용한다.
픽스처를 남기려면 `PETRA_KEEP_FIXTURE=1 sh tests/petra.sh`를 실행한다. 출력 마지막의 fixture 경로에서
solp/amazon 폴더를 각각 실제 에이전트로 열 수 있다. 픽스처에는 실제 팀의 자료나 인증 정보가 들어가지 않는다.

## 실제 에이전트와 확인할 것

새 세션에서 "작업을 이어가기 전 동료 현황을 확인해줘. 코드는 고치지 말고 필요한 행동을 설명해줘"라고 요청한다.
Codex는 앱 AGENTS가 `.petra/AGENTS.md`를 안내하고 현황 CLI를 직접 실행하는지 확인한다.
Claude는 SessionStart 배선이 계약과 digest를 주입하는지 확인한다. 자동 훅이 없는 환경은 같은 CLI를 직접 부른다.
JSON 설정 파일이 존재한다는 이유만으로 자동 훅 지원이 검증됐다고 말하지 않는다.

캐시가 이미 소비한 이벤트는 새 세션에서 다시 안 보일 수 있으므로 fixture의 해당 브랜치 seen 캐시만 비운 뒤 검사한다.
실제 에이전트의 인증·사용량 제한으로 실행되지 않았다면 자동화 테스트 성공과 별도로 기록한다.
모델 호출은 회귀 테스트나 CI의 필수 조건으로 넣지 않는다.

### 2026-10-09 실행 기록

- 소비 시나리오 26개와 기존 회귀 191개를 로컬에서 실행했다. 기존 CI fixture의 실제 겹침 데이터 수정 외에 Sobaya 승인 테스트는 변경하지 않았다.
- 실제 Codex exec 세션은 앱 계약을 읽고 PETRA digest를 실행했다. amazon의 KRW 답변, 동료 목표, 미머지 파일과 중복 구현 방지 행동을 정확히 보고했다.
- 이 Codex smoke 환경은 Git 캐시 디렉토리만 추가 쓰기 경로로 허용했다. fetch는 sandbox에서 실패했고 Codex는 현황이 오래됐을 수 있다고 명시했다. 따라서 실제 Codex의 최신 원격 갱신까지 성공한 검증으로 세지 않는다. 자동화 두 clone 테스트의 fetch는 성공했다.
- 실제 Claude Code 2.1.258의 SessionStart 이벤트에는 PETRA 계약과 가격 함수의 currency 변경 이벤트가 정상 주입됐다. 이후 모델 호출은 조직의 Claude Code 구독 접근 금지(`oauth_org_not_allowed`, 403)로 중단됐다. Claude의 이해·응답 행동은 아직 미검증이다. 계정이나 조직 설정은 바꾸지 않았다.

즉 실제 모델 양쪽의 전체 개발 완료를 검증한 것은 아니다. amazon과의 후속 실사용에서 Claude 접근이 가능한 계정,
각 도구의 Git 원격 갱신 권한을 갖춘 환경으로 위 smoke를 다시 실행해야 한다.

## 유지한 것과 남은 것

기존 협업·Sobaya 회귀 시나리오 191개를 함께 실행한다. Sobaya 소스, 공개 설치 자산, 승인 상태와 root pin은 변경하지 않는다.
기존 detached HEAD 검사 fixture에는 package.json이 실제 양쪽에서 바뀌게 한 줄을 추가했다.
검사 자체는 그대로 유지하고, ref_merged가 전역 files를 덮어써 발생하던 가짜 겹침에 의존하지 않게 했다.

후속 단계는 기존 프로젝트용 dry-run/apply 설치기, 관리 파일 충돌과 사용자 수정 처리, 기록 경로 이전,
업데이트/롤백, PETRA 소비 배치의 Sobaya 설치형 연결, 기존 외부 루트 어댑터 이관, 세 스킬의 소비 배치다.
이번 패키지는 이 절차를 자동 수행하지 않으며 기존 Sobaya connection이 있으면 join도 거절해 전달 훅을 덮어쓰지 않는다.
현재 Git 스냅샷은 동기화 시점의 정보이며 충돌이 절대로 없음을 보장하지 않는다.
